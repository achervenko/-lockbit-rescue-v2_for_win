# LockBit Rescue v2 — восстановление файлов после LockBit 3.0

Инструменты восстановления на основе повторного использования потока шифрования служебных данных FEI. Результат зависит от конкретной группы файлов и доступных известных байтов. Универсальный ключ не найден.

Проект основан на [CLXZ4353/lockbit-rescue-v2](https://github.com/CLXZ4353/lockbit-rescue-v2) и [Saddytech/lockbit-rescue](https://github.com/Saddytech/lockbit-rescue). Windows-версия — [achervenko/-lockbit-rescue-v2_for_win](https://github.com/achervenko/-lockbit-rescue-v2_for_win). Условия использования приведены в [LICENSE](LICENSE).

## Как это работает

1. Читаем служебный хвост и группируем файлы по одинаковому KEK blob. Fingerprint идентифицирует группу, но не раскрывает KEK.
2. Из известных имён и подтверждённых полей FEI получаем байты потока через XOR.
3. Восстанавливаем доступную часть FEK — модифицированного состояния Salsa20 для тела файла.
4. При достаточном покрытии выполняем прямую расшифровку, при небольшом неизвестном участке используем перебор.
5. Проверяем полный результат и выясняем, можно ли расширить покрытие для следующих файлов группы.

Последние 134 байта содержат длину FEI (2 байта), поле checksum (4 байта) и KEK blob (128 байт). Зашифрованный FEI расположен перед этим хвостом. В исследованных образцах FEI включает сжатое apLib имя UTF-16LE, метаданные и 64-байтовое состояние FEK.

Поток тела файла и поток FEI различаются. Наличие original/encrypted пары даёт XOR потока тела, но само по себе не раскрывает FEK или недостающий поток FEI.

## Состав репозитория

| Файл | Назначение |
|---|---|
| `lockbit_rescue_v2.py` | Сканирование, группировка, Phase 1/2 и манифест |

| `iterative_recovery_pairs.py` | Отдельный инструмент итеративного восстановления с парами |

| `verify_recovered_v2.py` | Базовая проверка результатов |
| `test_lockbit_rescue_v2.py` | Синтетические проверки реализации |
| `install.ps1`, `install.sh` | Установка и сборка |
| `research/gpu/recover_gpu.py` | OpenCL-перебор с CPU-проверкой и сохранением прогресса |
| `research/legacy/`, `research/later/` | Экспериментальные инструменты FEI, PDF, Z3 и восстановления |

| `AGENTS.md` | Правила дальнейшей работы |

Рабочая Phase 1 использует `direct-decrypt` и не требует запуска `stream-reuse.exe`. Старые исходники и параметры совместимости сохранены для истории.

CPU-helper поддерживает сигнатуры длиной до 64 байтов и окна поиска сигнатур. Исправлено чтение байтов на границе известного и подбираемого потока. В `direct-decrypt` используются 64-битные файловые смещения Windows. После изменений исходников бинарники нужно пересобирать.

## Исследовательские инструменты

Каталог [research/](research/README.md) содержит инструменты анализа FEI/FEK, объединения oracle, исследования метаданных и сжатых имён, CPU/GPU-перебора, Z3/SMT, построения профилей PDF и частичного извлечения мультимедиа.

Основной CLI и исследовательские сценарии имеют разные интерфейсы. Для экспериментальных скриптов требуется конфигурация конкретного набора данных. Порядок настройки и ограничения описаны в [документации research](research/README.md).

OpenCL-worker поддерживает неизвестный хвост FEK длиной до 6 байтов, проверку кандидатов на CPU и возобновление по завершённым batch. Перед использованием выполните аппаратный selftest. Производительность зависит от GPU, драйвера и параметров задачи.

Результаты восстановления учитываются в манифесте каждого запуска. Процент успеха зависит от повторения потока, доступного покрытия FEI и качества проверки выходных файлов.

## Установка на Windows

Нужны Windows x64, Python 3.10+, Git и GCC из MSYS2 UCRT64.

В MSYS2 UCRT64 выполните:

```bash
pacman -Syu
pacman -S mingw-w64-ucrt-x86_64-gcc make
```

Если обновление требует закрыть терминал, откройте его повторно перед установкой пакетов.

В PowerShell:

```powershell
git clone https://github.com/achervenko/-lockbit-rescue-v2_for_win.git
cd ./-lockbit-rescue-v2_for_win
$env:PATH = "C:\msys64\ucrt64\bin;C:\msys64\usr\bin;" + $env:PATH
python -m pip install -r requirements.txt
powershell -ExecutionPolicy Bypass -File ./install.ps1
```

Linux: установите GCC, make, Python и libmagic, затем выполните `python3 -m pip install -r requirements.txt` и `bash install.sh`. Совместимость последних доработок с Linux проверяйте отдельно.

## Запуск

Источник и результат должны находиться в разных каталогах. Начните с небольшой копии набора и ограниченного числа потоков.

```powershell
$env:OMP_NUM_THREADS = '2'
python ./lockbit_rescue_v2.py ./encrypted ./output --ext .xzg9VRelb --workers 2
```

Подбор до трёх байтов с таймаутом 30 минут:

```powershell
python ./lockbit_rescue_v2.py ./encrypted ./output --ext .xzg9VRelb --workers 2 --phase2 --max-brute-bytes 3 --brute-timeout 1800 --resume
```

`--workers` и число потоков OpenMP могут управлять разными уровнями параллелизма. Учитывайте их совокупную нагрузку. Фильтры размера и расширения могут пропускать файлы; изучите `--min-size`, `--max-size`, `--no-extension-filter` через `python ./lockbit_rescue_v2.py --help`. Параметры chunking по умолчанию не являются доказанными для каждого образца.

```powershell
python ./verify_recovered_v2.py ./output --json
python ./fei_layout_analysis.py --remaining-priority ./encrypted
```

Отдельные исследовательские скрипты могут содержать настройки локального набора. Перед запуском изучите их пути и параметры.

## Gap и возобновление перебора

Gap — число фактически неизвестных байтов, необходимых целевому FEK. Расчёт только по длине FEI и непрерывному префиксу бывает неточен. Для анализа храните sparse-карту `offset -> byte`, источник и уверенность.

Для N независимых неизвестных байтов пространство равно `256^N`. Каждый дополнительный байт увеличивает его в 256 раз. Время полного перебора оценивайте по измеренной скорости конкретного worker'а. Более строгий фильтр кандидатов сам по себе не уменьшает это пространство.

Высокие таймаут и `--max-brute-bytes` не гарантируют поддержку такого перебора конкретным helper'ом. Штатный CPU-helper и специализированные GPU-worker'ы имеют разные ограничения.

`--resume` сохраняет состояние восстановления файлов. Он не гарантирует сохранение позиции внутри перебора одного файла. Для длительных экспериментов использовались отдельные чанки и checkpoint-worker'ы; их ограничения и новый OpenCL-worker описаны в `research/README.md`.

## Контроль качества

Заголовок и статус SUCCESS не подтверждают полное восстановление. Проверяйте:

- PDF — структуру, страницы, декодирование потоков и визуальный рендер. Открывающийся PDF может содержать повреждённую часть страницы.
- DOCX/XLSX/PPTX — ZIP, CRC, `[Content_Types].xml` и ожидаемые части Office.
- Фото — полное декодирование. Видео — всю длительность, звук, скорость и синхронизацию.
- CAD — открытие в родном приложении и зависимости. Сигнатура контейнера даёт только предварительную проверку.

Конфликтные байты oracle исключайте до выяснения причины и сохраняйте оба источника. Успешная расшифровка не обязательно расширяет покрытие группы. Частичный salvage учитывайте отдельно.

Z3 и профили PDF пока не дали подтверждённого общего способа уменьшить большие неизвестные участки до доступного перебора. `unknown` не доказывает отсутствие решения; `sat` требует полной проверки файла.

## Проверки реализации

```powershell
python -X utf8 ./test_lockbit_rescue_v2.py
```

Синтетические тесты не доказывают корректную расшифровку реальных документов. В Git публикуются код и обезличенная документация. Рабочие документы, пары, реальные FEK/keystream, приватные пути, логи и checkpoint-файлы храните отдельно.
