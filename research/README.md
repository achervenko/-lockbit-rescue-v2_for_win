# Собранные исследования по расшифровке

Здесь собран доступный на ноутбуке код из двух рабочих каталогов. Точный список, размеры и SHA-256 оригинальных файлов находятся в `inventory.json`. Это архив исследований и переносимые копии скриптов, а не один универсальный проверенный дешифратор.

## Что куда положено

| Каталог | Содержание |
|---|---|
| `legacy/` | 129 исторических Python-скриптов: FEI/FEK, пары, PDF, Z3, CPU-перебор, видео, отчёты, ZUP |
| `later/` | 7 скриптов более позднего исследования: подбор с масками, цепочка и подготовка GPU-задачи |
| `native/` | C-исходники и apLib header; реальные константы задач вынесены отдельно |
| `gpu/` | Отдельный OpenCL-worker с manifest, CPU-проверкой результатов и checkpoint |
| `_local/` | Полные неизменённые оригиналы, старые бинарники, исходные заметки и приватные параметры; исключены из Git |

Исторические инструкции, PS1/CMD-launcher'ы и бинарники сохранены в локальном архиве без изменений. Не запускайте их автоматически: они могут ссылаться на старые каталоги, использовать все CPU-потоки и содержать старые ошибки возобновления. В публичной части сохранены Python-генераторы нативных worker'ов и исходники их алгоритмов.

## Как устроены переносимые копии

В исторических скриптах были абсолютные пути, имена документов и данные конкретных задач. В экспортированных копиях такие строковые значения заменены обращениями к приватному профилю. Локальные ссылки на код направлены на текущий репозиторий. Исходные версии сохранены побайтово в `_local/originals/`.

Для повторения прежних экспериментов на исходном ноутбуке:

```powershell
python -m pip install -r ./research/requirements.txt
$env:LOCKBIT_CASE_VALUES = (Resolve-Path ./research/_local/case_values.json).Path
python ./research/legacy/recover_desktop_tree.py
```

Последняя команда запускает восстановление с настройками прежнего набора. Сначала проверьте пути в приватном профиле и доступную нагрузку. Сборка комплекта сама восстановление не запускает.

После клонирования на другом устройстве создайте собственный `research/case_values.json` на основе `case_values.example.json`. Значения зависят от эксперимента; пример содержит только идентификаторы и заглушки. Часть архивных скриптов требует старых отчётов, seed-файлов или восстановленных документов, которые не публикуются. Без входных данных воспроизводятся алгоритмы, но не прежний результат.

Для C-файлов с `#include "private_case.h"` локальные определения сохранены в `_local/native/<набор>/<имя>/private_case.h`. Укажите соответствующую папку через `gcc -I...` или сгенерируйте задачу заново соответствующим Python-генератором. Эти headers содержат реальные данные и не должны попадать в Git.

Бинарники из `_local/originals/` не копируются в исполняемые пути автоматически. Их нужно пересобрать из соответствующих исходников. Для `recover_desktop_tree.py` нужен `aplib_name_pack.exe` в `research/legacy/`; исходник находится в `native/legacy/aplib_name_pack.c`. Основные helper'ы собираются штатным installer'ом в корне.

Проверенная команда сборки packer в MSYS2 UCRT64 или PowerShell с GCC в PATH:

```powershell
gcc -O2 -I ./_stream-reuse ./research/native/legacy/aplib_name_pack.c ./_stream-reuse/aplib-src/lib/coff64/aplib.lib -o ./research/legacy/aplib_name_pack.exe
```

В корневых инструментах `fei_layout_analysis.py` и `iterative_recovery_pairs.py` входы настраиваются переменными `RECOVER_SOURCE`, `RECOVER_OUTPUT`, `RECOVER_PAIRS` и `RECOVER_FEI_REPORTS` (последние две — для анализа FEI). Значения по умолчанию относительные.

## GPU-перебор

Найденный OpenCL-worker происходил из более позднего пакета для группы `04b4776408a3`. Тождество с быстрым kernel'ом исторического 6-байтового прогона на RTX 3060 не установлено. Скорость 5,5 млрд/с для этой версии не измерялась.

Переносимая версия находится в `gpu/recover_gpu.py`. Для неё добавлены выбор manifest, привязка checkpoint к задаче и версии worker'а, проверка путей, независимый запуск selftest и возможность явно разрешить gap=6. По умолчанию максимум 5 байтов. Новая 6-байтовая ветка требует аппаратной проверки перед долгим запуском.

Установите драйвер GPU с OpenCL и зависимости:

```powershell
python -m pip install -r ./research/gpu/requirements.txt
python ./research/gpu/recover_gpu.py --selftest
```

Для задачи создайте приватный каталог с `manifest.json` и `data/`, используя `gpu/manifest.example.json`. Укажите подтверждённый непрерывный FEI-keystream, реальные длины FEI, SHA-256 зашифрованных файлов и цепочку целей. Пример не содержит реальных ключей и не является готовой задачей.

```powershell
python ./research/gpu/recover_gpu.py --manifest ./private-task/manifest.json --max-gap 6 --batch-power 24
```

Не запускайте два процесса с одним manifest/checkpoint. Прогресс сохраняется после завершённого batch атомарной заменой JSON. Незавершённый batch после сбоя повторяется. `progress.json` содержит ключевые данные и остаётся приватным. Новый worker не принимает checkpoint старой версии без идентификатора задачи; старое состояние нужно сохранить и разбирать отдельно.

Этот worker работает с непрерывным известным префиксом и неизвестным хвостом FEK длиной 1–6 байтов. Он не решает произвольные sparse-пропуски. Проверяет PDF, Office ZIP, OLE и JPEG; правила chunking унаследованы от конкретного исследованного образца и требуют проверки для новой группы. Документ целиком держится в памяти, поэтому крупные файлы требуют оценки RAM.

CPU-проверка полного файла выполняется перед принятием кандидата. Рендер PDF включён для финальных целей. Это не означает полной проверки CAD в SolidWorks или безусловной корректности промежуточного Office-документа. Усиление фильтра не уменьшает пространство перебора.

## Основные направления

- `recover_desktop_tree.py` — массовое восстановление и объединение oracle.
- `analyze_sklad_fei_metadata.py`, `metadata_profile_analysis.py`, `reconstruct_fei_model_4f.py` — устройство FEI и гипотезы metadata.
- `make_gap6_bruteforce_4f_fast.py`, `run_gap6_*`, `make_smart_bruteforce_624.py` — генераторы CPU-перебора и исторические checkpoint-launcher'ы.
- `solve_*`, `z3_*` — Z3/SMT, общие неизвестные байты, ограничения по парам и заголовкам.
- `target_group_pdf_profile.py`, `pdf_profile_*`, `overnight_pdf_prefix_search.py` — профили PDF и проверки гипотез plaintext.
- `repair_recovered_videos.py`, `salvage_*` — мультимедиа и частичное извлечение; salvage не считать полной расшифровкой.
- `zup_*`, `inspect_zup_fei.py`, `try_zup_*` — исследование базы ZUP, успешной расшифровки базы нет.

## Что проверено при сборке

Синтаксис экспортированных Python-файлов, целостность локальных копий по SHA-256, удаление прямых приватных путей из экспортированного кода, тест преобразования исходников, CPU-вектор Salsa20 и проверки checkpoint/path containment GPU-worker'а. Итоговый список выполненных проверок находится в `VALIDATION.md`.

Все исторические сценарии не запускались повторно. Обновлённый GPU-код на видеокарте не проверен. Не считайте наличие файла в архиве доказательством работоспособности каждого эксперимента или прироста восстановленных документов.
